# Telegram

## Transport / handlers

- Entry: `UpdateProcessor` (poll + webhook share it).
- Outbound API: `TelegramClient` via Laravel `Http` (fakeable). Пакет `irazasyed/telegram-bot-sdk` в composer **не** используется кодом (legacy dep).
- Handlers map updates to Services/Actions; no domain mutations inline beyond orchestration already in Services/Quests.
- Callback prefixes: `ob:` `quest:` `menu:` `inv:` `bag:` `gear:` `stat:` `smith:` `fight:` `city:` `portal:` `daily:` `journal:` `lib:` `appeal:` `pvp:`. Legacy alias: `backpack:` → `inv:` (и `menu:backpack*` → `menu:inv*`) в `InventoryHandler`.
- Appeal UI (`/appeal` / `appeal:*`): photo `menu/appeal-letter.png` (`bot.appeal_image`) + caption `<b>Обращения · N</b>`; list своих обращений (`PaginatedListKeyboard` без фильтров, filter=`all`); row `d.m.Y · статус`; footer только `Оставить заявку` success → `appeal:new` (**без** Назад на списке); empty → italic `telegram.appeal.empty` + тот же footer; карточка `appeal:card:{id}` — текст + статус + `« Назад` · `Снять заявку` (без style; только NEW/READ); тело в `<blockquote>`; снятие → confirm Нет/Да; compose — await текста (cache `appeal:await:{tg_id}`, TTL `settings.appeal.awaitTtlSeconds`); create → edit якоря списка + `telegram.appeal.created`; лимиты `maxBodyLength` / `cooldownSeconds` / `maxOpenAppeals`. В бою ignore (как другие menu-команды).
- Library UI (`/library` / `lib:*`): home photo `menu/library-closed.png` + `telegram.library.home` + Локации · Экипировка / Зелья · Камни / Статы · Бой / Существа · Мини-игры / Жители · Контракты; все списки/карточки разделов — `menu/library-opened.png` (без арт локаций/NPC/врагов/арены/доски); локации (`lib:loc`) — full-width gates/board/training, остальное 2×N + « Назад → `lib:home`; карточка `lib:loc:{key}` → `telegram.library.locations.*`; экипировка (`lib:gear`) — Использование / Инкрустация → `lib:gear:{wear|socket}` + `telegram.library.gear.*`; зелья (`lib:pot`) / камни (`lib:gem`) / статы (`lib:stat`) / бой (`lib:combat`) / контракты (`lib:contract`) — сразу карточка + « Назад → `lib:home`; существа (`lib:enemy`) — 2×N → `lib:enemy:{catalog_id}` + `telegram.library.enemies.*`; жители (`lib:npc`) — 2×N → `lib:npc:{key}` + `telegram.library.npcs.*`; мини-игры (`lib:game`) — Бочки удачи → `lib:game:lucky_barrel` + `telegram.library.minigames.*`. Read-only; в бою `/library` ignore. After player-facing changes — sync checklist in [`.ai/guidelines/library.md`](../guidelines/library.md).
- Journal UI (`/journal` / `journal:list:{filter}:{page}`): photo `menu/contracts.png` (`bot.journal_image`) + caption `<b>Задания · N</b>`; empty → italic `telegram.journal.empty` без кнопок; при контрактах — `PaginatedListKeyboard` с `backCallback=null` (фильтры `all`/`hunt`/`delivery` = Все/Заказы/Просьбы; дефолт/открытие = `all` + `primary`; items×5, пагинация; **без** Назад на списке); только взятые (`accepted`/`ready`/`completed`); карточка `journal:card:{id}:{filter}` — текст как доска (`telegram.daily.card` / `card_delivery`) + photo для delivery (hunt — caption на `contracts.png`); один ряд `« Назад` danger → `journal:list:{filter}:1`; возврат на список → `editMessageMedia` снова на `contracts.png` (fail → caption / delete+sendPhoto); без accept/hunt/turn-in.
- Backpack UI (`/backpack` / `menu:inv` / `inv:list:{filter}:{page}`): photo `menu/backpack.png` (`bot.backpack_image`) + caption `<b>Рюкзак · N/M</b>`; empty → italic `profile.inventory_empty` без кнопок; при вещах — `PaginatedListKeyboard` с `backCallback=null` (фильтры только WEAPON/ARMOR/JEWELRY; дефолт/открытие = `WEAPON` + `primary`; items×5, пагинация; **без** Назад на списке); карточка `inv:card:{id}` — photo `equipment/{catalog_id}` + один ряд `« Назад` danger · `Выбросить` (без Надеть/камней/Сумка/Gear; надеть — из куклы `gear:pick`); возврат на список / discard → `editMessageMedia` снова на `backpack.png` (fail → caption / delete+sendPhoto); discard confirm — ряд `Нет` danger · `Да` success; после Да — notice `profile.discarded` под хедером. Equip/unequip с куклы без изменений.
- Bag UI (`/bag` / `menu:bag` / `bag:list:{filter}:{page}`): photo `menu/bag.png` (`bot.bag_image`) + caption `<b>Сумка · N/M</b>` (`bagRowCount` / `bag_max_rows`); empty → italic `profile.bag_empty` без кнопок; при вещах — `PaginatedListKeyboard` с `backCallback=null` (фильтры POTION/GEM/QUEST; дефолт/открытие = `POTION` + `primary`; items×5, пагинация; **без** Назад / кузнец / рюкзак на списке); зелья в списке — `profile.bag_potion_row` = `:name ×:quantity` (стак до `potionMaxStack`; камни/квест — по 1 слоту, камни `(current/max)` = durability); карточка `bag:card:{id}` (legacy `bag:gem|potion|quest:{id}`) — photo `resource/{catalog_id}` + один ряд `« Назад` danger · `Выбросить` (Назад → `bag:list:{kind}:1`); gem-карточка как shop-card (`bag_gem_card` / `_no_desc`: имя → desc → тип → МФ → 🔧); возврат на список / discard → `editMessageMedia` снова на `bag.png` (fail → caption / delete+sendPhoto); discard confirm — ряд `Нет` danger · `Да` success; после Да — notice `profile.discarded` под хедером; пустой фильтр при непустой сумке → `profile.bag_empty_type`. Socket камней — **не** из `/bag`.
- Gear gem socket (кукла): пустой слот → `gear:gem:pick:{host}` (+ `:pick:{slot}` если карточка из `gear:pick` / `inv:card:{id}:pick:{slot}`) → список loose gems → `gear:gem:ask:{host}:{gem}`[+`:pick:{slot}`] — арт камня + `bag_gem_card` + `profile.gear_gem_socket_warn` + ряд `Нет` danger · `Да` success → `gear:gem:socket:…`; Нет → снова pick-list; Да → socket; after: одетая → `gear:view:{host}`, неодетая с pick → `inv:card:{host}:pick:{slot}` (не `inv:list`); вставленный → `gear:gem:view` (без warn/socket). Unsocket запрещён. Кузнец (`smith:gems`) — отдельный legacy-вход.
- Gear equip/unequip: не в один клик — `inv:eq:ask` / `inv:uneq:ask` → confirm-caption (title + дельты через `LoadoutService::*StatChanges` / `EquipPreviewText`, лейблы статов из `menu.stat_*`: ❤️/⚔️/🛡/🤺/🎯/💥/🪨) + ряд `Нет` danger · `Да` success → `inv:eq:yes` / `inv:uneq:yes`. Админка — текстовые лейблы через `BackpackEquipPreviewHtml`.
- Handler routing: `QuestHandler` (`quest:overseer:*` / `quest:healer:*` / `quest:blacksmith:*` / `quest:bruiser:*` / `quest:buyer:*`), `DailyContractHandler` (`daily:*` — доска/охота/сдача), `JournalHandler` (`journal:*` / `/journal`), `LibraryHandler` (`lib:*` / `/library`), `AppealHandler` (`appeal:*` / `/appeal`), `InventoryHandler` (`inv:`/`bag:`/`gear:`/`menu:inv|bag|gear`), `SmithHandler` (`smith:`/`menu:smith`), `BarkeeperHandler` (`city:barkeeper*` — оффер + daily + Бочка Удачи / `lucky_barrels`), `BruiserHandler` (`city:bruiser` — delivery turn-in в порту), `BlacksmithHandler` (`city:blacksmith*` — shop/repair в таверне / delivery в лесу; стойка+ремонт: имя → `view` → карточка + цена → buy/do; repair_all → confirm Нет/Да), `HealerHandler` (`city:healer*` — shop в таверне / delivery в руинах; оффер: Полка + ряд Назад·Зашить → confirm Нет/Да → `heal:yes`), `BuyerHandler` (`city:buyer*` — таверна / delivery на доске; ларец: имя → `chest:view` → карточка → buy; продажа: имя → `sell:view` → карточка + Нет/Да → `sell_yes`), `OverseerHandler` (`city:overseer*` — таверна / delivery intercept с `city:home`; оффер: статы + ряд Назад·Сброс → confirm С/Л/И/Ж+🥇 · Нет/Да → `reset_yes`), `MenuHandler` (profile/stats/commands), остальные — как раньше.
- Idle + портал: `LuckyBarrelForfeitAction` — kill `lucky_barrels` IN_PROGRESS (ставка уже списана, без возврата). Назад на play (`city:barkeeper:game:back`) — тот же forfeit → оффер.
- Daily delivery placement: `QuestNpcPlacement` + `NpcEnum::deliverySpot()` — overlay **только** в `target_city_id` при `accepted`; hunt сдача = таверна. Overseer delivery: intercept `city:home`, later/done → `city:hub` (не кнопка на корне). Канон — [`docs/quests/DAILY_QUESTS.md`](../../docs/quests/DAILY_QUESTS.md) §4.1.
- Handlers — плоско в `app/Telegram/Handlers/` (`RegistrationHandler`, `QuestHandler`, `CityHandler`, …), без подпапок по флоу. Services/Actions по-прежнему в `Registration/` / `Quest/` / `Fight/` при ≥2 файлах.
- Keyboards: `CityKeyboard`, `RegistrationKeyboard`, остальное — `TelegramKeyboards`; общий helper — trait `BuildsInlineKeyboard`. Все кнопки «Назад» (`telegram.btn.back` / `menu.back` / `registration.btn_back` / `menu.back_to_slot`) — `style: danger`. Пара «отказ / подтверждение» в **одном ряду**: слева отказ/`danger` (красный), справа подтверждение/`success` (зелёный) — напр. «Пройти мимо» · «Принять вызов», «Нет» · «Да». Не наоборот. Длинные списки (скупщик/кузнец/лекарь/портал/доска): `PaginatedListKeyboard` — фильтры (active = `style: primary`) + items по 5 + `«` / `N/M` / `»` + Назад `danger` (ларец: все/камни/обереги; доска: все/заказы/просьбы); лес / зал / список боёв — без фильтров, только items + пагинация + Назад; кнопка `N/M` → `{prefix}:listpage:{page}:{pages}` → toast `telegram.btn.page_toast` (без edit панели); state списка в `{prefix}:list:{filter}:{page}`; `totalCount=0` (нет items ни в одном фильтре) → только Назад (без фильтров/пагинации); пустой текущий фильтр при `totalCount>0` → фильтры есть, пагинации нет; край страницы (есть items) → **edit** `*_empty` на 5с, потом detached `telegram:restore-list-panel` возвращает обычный текст (клавиатура clamp page); пустой список — `*_empty` без revert; не toast. `FlashListPageEdgeAction` + generation в cache; любой `TelegramResponder` edit/editPhoto* делает `touch` и отменяет pending restore (уход с экрана за 5с не затирается). Не `queue:background`/`defer` — в `telegram:poll` defer не срабатывает, sync+delay затирает flash сразу. Fight UI: **одно** photo + inline (`fightInlineForStep`): caption = `panelCaption` (статус + «Раунд N. Выбери…»); STANCE = стойка + зелья, ATTACK = `fight:atk:*`, DEFEND = `fight:def:\*`; на любом шаге (не tutorial, не PVP) — `fight:flee` danger. Побег: шанс как dodge; fail → skip-раунд; success → soft lose (`finishFlee`) + `returnAfterFight`. Callbacks → `FightHandler::handleCallback`.

Старт с pick (лес/зал/… photo-callback): `open` → **editMessageMedia** (арт врага + caption/inline); без photo / fail → send. Ходы: `editMessageCaption`(+inline); fail → delete+resend. **Turn timeout** (`settings.combat.turnTimeoutSeconds`, канон 30): один дедлайн на весь wizard; `FightService::scheduleTurn` → `turn_deadline_at` + `FightTurnWatchJob` (тик `turnTickSeconds`=5 → edit caption с `combat.turn_timer` под step-prompt; на дедлайне → `runSkipRound` / PVP `submitSkip`). Lazy в `FightHandler` до stance/atk/def/flee. При skip (timeout / flee fail) — `combat.turn_skipped` / `combat.turn_timeout`. Ошибки хода (зелье и т.п.) — `showError`: caption = статус + ошибка + таймер, без нового сообщения. Конец боя (зал/лес/flee/PVP): edit caption + inline «Итоги боя» (`fight:report:*`, cache summary/log TTL=`idleSessionSeconds`), затем `CityHandler::returnAfterFight` шлёт **новое** сообщение локации (лес/тренировка / PVP список через `PvpHandler::sendList`), отчёт боя остаётся (toggle caption ↔ лог). **Квестовые** follow-up (`FightEndUiEnum::OverseerStats` / `Intro` и далее quest-экраны после боя): **edit** той же панели боя (арт NPC + caption + inline), не `sendPhoto`/`sendMessage`. Обычный PvE/зал — по-прежнему новое сообщение локации. Legacy `tg_log_message_id` при refresh/end удаляется. `tg_reply_kind` + `last_round`.

## Player-facing copy (обязательно)

Канон флоу / механики — `docs/telegram/` (`REGISTRATION.md`, `CITY.md`, `GATES.md`, `PORTAL.md`, `FOREST.md`, `ARENA.md`, `TRAINING.md`, `TAVERN.md`, `HEALER.md`, `BLACKSMITH.md`, `SHOP_CARD.md`) + `docs/quests/CHAPTER_1.md`.  
Перед правкой поведения: прочитать соответствующий файл и соседние экраны того же флоу.  
Витрины NPC (лекарь / кузнец / скупщик / …): покупка только через карточку товара — [`docs/telegram/SHOP_CARD.md`](../../docs/telegram/SHOP_CARD.md) (список без цены → `view` → карточка → `buy`). Не делать buy в один клик со списка.

Стиль сообщений:

- 2-е лицо («ты»), атмосфера мира; короткий системный сухой тон — только если так явно в каноне флоу.
- Одна непрерывная история на флоу: каждый экран опирается на предыдущий. Не противоречить уже сказанному (где герой, есть ли имя/город).
- Ошибки — в том же голосе, что соседний экран, плюс ясный next action.
- Строки игроку — в `lang/ru/` (`__()`), не хардкод в Services/Actions/Handlers.
- **Именованные сущности — с большой буквы** (и в кнопках, и в прозе, во всех падежах). Канон голоса — `README.md` (демо для игроков) + `telegram.btn.*` / `telegram.commands.*`. Не писать «таверна / арена / кузнец» строчными, если речь о локации, NPC или системе игры.
  - Локации / хаб: `Город`, `Городские ворота`, `Таверна`, `Доска объявлений` (кратко `Доска`), `Арена`, `Портал`, `Лес`, `Болото`/`Болота`, `Руины`, `Порт`, `Тренировочный зал`, `Ристалище`, `Список боёв`.
  - NPC: `Смотритель`, `Лекарь`, `Кузнец`, `Скупщик`, `Трактирщик`, `Громила`.
  - Инвентарь / меню: `Рюкзак`, `Сумка`, `Профиль`, `Экипировка`, `Задания`, `Библиотека`.
  - Мини-игра: `Бочки удачи` (как `telegram.btn.lucky_barrel`).
  - Исключения (строчные ок): деревянные «доски» указателя на регистрации; бытовая «сумка» как квестовый предмет Кузнеца (не инвентарь); прилагательные вроде «болотные крысы», «лесные мобы».

## Economy marks (монеты / опыт)

Формат в TG-копирайте и кнопках:

- **Дельта** (награда / выручка / трата): `🪙 +N` / `🪙 -N`, `🥇 +N` / `🥇 -N`, `⭐️ +N` / `⭐️ -N` — иконка, пробел, знак, число. Пример канона: `combat.win` (`⭐️ +:exp` / `🪙 +:silver`).
    - награда / продажа / выручка → `+`
    - покупка / ремонт / сброс / портал / снятие камня → `-`
- **Баланс** (сток на руках): `🪙 N` / `🥇 N` / `⭐️ N` — иконка перед числом, без знака.
- Запрещено: `N🪙`, `:price🪙`, `+:price:mark`, `опыт: N`, иконка после числа.

## Formatting (HTML)

Все исходящие тексты (`TelegramClient::sendMessage` / `editMessageText` / `sendPhoto` caption / `editMessageCaption`) уходят с `parse_mode=HTML`.

- В `lang/ru/` для бота — Telegram HTML: `<b>`, `<i>`, `<u>`, `<s>`, `<code>`, `<pre>`, `<blockquote>`, `<a href="...">`, `<tg-spoiler>`. Не Markdown.
- **Переносы строк в `lang/ru/*.php`:** если в строке есть `\n`, значение **обязательно** в двойных кавычках `"..."`. В одинарных `'...'` PHP не разворачивает `\n` — в Telegram уезжает литерал `\n`. Пример: `"…мысли.\n\nВыбери…"`, не `'…мысли.\n\nВыбери…'`.
- **Нарратив игроку (обязательно):** экранный текст, ошибки, подсказки, caption — обернуть в `<i>…</i>` (курсив по умолчанию). Касается `lang/ru/telegram.php`, `errors.php` (игрок-facing), `combat.php` / `menu.php` / … где уходит в ТГ, и `cities.description` в админке/сидере.  
  Акцент внутри курсива — `<b>…</b>` (ник, имя города и т.п.).  
  Пример: `telegram.registration.splash`, `pick_city`, `telegram.npc.overseer.first_home` (нарративные куски).
- **Речь любого NPC (обязательно):** прямая речь — только в `<blockquote>…</blockquote>` (полоска + кавычки в клиенте Telegram). Касается экранов, отказов, офферов, реплик в `telegram.*` и `errors.*`, если говорит персонаж (Смотритель, лекарь, кузнец, скупщик, …).  
  Нарратив вокруг («он кивает», «отодвигает кружку») — в `<i>…</i>` **вне** blockquote (отдельные куски `<i>` до/после цитаты — ок).  
  **Запрещено** оформлять речь NPC кавычками `«…»` / `"…"` без `<blockquote>`. Пример канона: `telegram.npc.overseer.first_home`, `telegram.npc.overseer.skip`, `telegram.npc.healer.error.already_full`.
- Динамику (`username`, города, предметы, имена в логе боя и т.п.), подставляемую в текст сообщения, **всегда** экранировать через `TelegramHtml::escape()` **до** `__()` / склейки. Иначе `&` / `<` / `>` ломают parse или дают 400 от Telegram. Текст внутри `<blockquote>` / `<i>` / `<b>` тоже экранировать, если туда попадает динамика.
- Рандомные варианты ошибки/копирайта — массив строк в lang, показ через `LangVariant::pick(...)` (registration: `telegram.registration.error.*`; не Markdown-списки в одном ключе). Каждый вариант — тоже в `<i>…</i>`.
- Кнопки (`callback` label) parse_mode не получают — HTML-теги в текстах кнопок не использовать.
- Не экранировать целиком уже собранное сообщение с тегами — только сырые значения.

Перед подключением картинки в бот (`config/bot.php`, Spatie media, `sendPhoto` / `editMessageMedia`) — **проверить файл**, не класть «как вышло из Figma».

Канон рабочих артов:

- PNG, **RGB** (не RGBA/LA; «пустая» альфа 255 тоже риск — клиент ТГ иногда показывает крест при ок API)
- размер панели как у существующих: **512×384**
- без ancillary-чанков Figma (`sRGB` / `gAMA` / `tEXt` и т.п.) — plain PNG
- IDAT-чанки умеренные (ориентир ≤64 KiB каждый); один гигантский IDAT — перекодировать
- вес порядка сотен KB (как соседние файлы в той же папке), не мегабайты

Проверка перед wiring: `file`, режим цвета / размер (`sips` / Pillow), сравнить с уже рабочим артом в той же подпапке.  
Плохой экспорт → пересохранить в RGB PNG (`convert('RGB')` / экспорт без альфы), потом уже `config('bot.*_image')` / media.
